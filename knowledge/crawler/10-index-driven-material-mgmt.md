# 索引驱动的素材管理体系

> 来源：智能照明方案馆素材重构（2026-07-25）
> 关键词：场景化目录 · 索引交叉引用 · clean_text 清洗 · 大规模素材管理

## 核心架构：索引驱动，不物理移动

### 传统做法 vs 索引驱动

**传统做法**：HTML 下载 → 按场景物理迁移文件 → 目录深 → 交叉引用难

**索引驱动方案**：

```
refs/{scene}/
├── _素材索引.md          ← 唯一交叉引用入口
├── kingsun_detail/       ← 按厂商存放，不物理移动
├── ltech_detail/
└── fsl_detail/
```

### 核心原则

1. **文件按源（厂商）存放**，永不清零物理路径
2. **场景归属通过索引定义**，一个素材可出现在多个场景的索引中
3. **索引是唯一视图**，清洗、展示、引用都通过索引，不碰原始文件
4. **新增场景 = 新增索引**，不需要改目录结构

## clean_text 全量清洗流水线

### 执行流程

```bash
python3 clean_text.py --all
```

**输入**：283 个原始 markdown 文件（含 HTML 残留、4K 导航栏、表格格式等）
**输出**：277 OK，6 跳过（损坏或非文本文件）

### PAK 清洗规则（示例）

```
PAK 原文特征:
- `<h1>PAK Corporation</h1>` 排版头
- `<div class="nav">...</div>` 全站 4KB 导航 HTML
- `<img src="...">` 内嵌图片引用

clean_text 处理:
- 移除导航/页脚 HTML（正则匹配 `<div class="nav|footer">`）
- 保留标题 + 正文 markdown
- 图片引用保留为 `![描述](url)`
```

### 清洗要点

- 导航 HTML 通常占 30-50% 文件体积 → 移除后压缩率可能触发 >50% warning，实际正常
- 图片外链保留不删除（manual 图片通过索引标注）
- html2text 用于 HTML→Markdown 转换（Python 3.13 需额外安装，不在原始 requirements.txt 中）
- 清洗脚本独立于采集器，可单独迭代

## _素材索引.md 结构

### 生成命令

```bash
python3 generate_index.py
```

### 索引格式

```markdown
# 办公场景 - 素材索引

| 标题 | 来源 | 字数 | 图片 | 摘要 |
|------|------|------|------|------|
| PAK 办公照明方案 | pak_detail | 2,150 | 8 | office lighting... |
| 雷士办公案例 | kingsun_case | 3,800 | 25 | open office... |
```

### 注意事项

- 摘要从原始 markdown 头提取（非清洗后正文）→ 需后续改进
- 字数统计含图片 alt 文本 → 在可接受范围内
- 下载图片 vs 外链未下载图片分别统计（已下载 2,111 / 未下载 2,298）

## 大规模图片管理策略

### manual 图片标注

```
场景：ltech（1,453 张外链）/ fsl（845 张外链）防盗链无法自动下载

策略：
1. 不自阻塞流程 —— 清洗、索引、展示照常
2. 索引中标注 manual 图片数
3. 图片引用保留原始 URL（在线查看有效）
4. 后续可通过浏览器插件或代理批量下载
```

- Q: 索引驱动素材组织的核心原则是什么？

- Q: clean_text 全量清洗的执行流程和典型规模？
