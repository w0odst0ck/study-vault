# S1 价格监控（monitor）— 知识手册

> 学习侧手册（2026-08-08 补建，S1 毕业答辩后）。产品设计权威源：PageHarvest
> `docs/plan/monitor.md`（含表设计/抓取层/时机判断/毕业评审标准答案）——本文件是
> 学习视角提炼 + 必答问题 + 误解纠正，两文件分工：产品文档 vs 学习手册。

## 1. 必答问题（S1 核心 5 题）

1. **monitor 在 PH 里的定位是什么？** 自动下游 · 静默 · 波动才提醒。消费离线解析产物，纯分析**无爬虫**；与 api/web/cli 平级（PH 一级功能，非独立项目）
2. **数据链路全貌？** PH 解析产物（CSV）→ 定时扫描导入（增量）→ 跨批次比价 → 波动检测 → 明显波动写 alerts → 心跳播报。数据属于用户，不上传
3. **什么算"明显波动"？怎么防首报假警？** price_low 主口径（最低可成交价）；阈值默认 ±5% 可配置（PRICE_OVERRIDES 按商品覆盖）；**静默学习期：快照 <3 条不输出信号**
4. **提醒闭环怎么防轰炸？** 冷却窗口 3 天 + 幂等键 (商品, 信号, 价格档位, 窗口) + consume_notified 标记 notified=1；升级方向：冷却按商品维度 + 拐点报告
5. **设计权衡三原则？** 数据契约解耦（不 import core/，红线+解耦）；无常驻进程（外部 cron 触发）；事件驱动（有波动才出声）

## 2. 核心设计（6 考察点，毕业评审标准）

| # | 考察点 | 实现 |
|---|--------|------|
| 1 | 数据入口/新批次 | `cli ingest --dir` 增量扫描，`.monitor_scan_state`（JSON：相对路径→{mtime,size}），只处理新增/变化文件 |
| 2 | 波动判定/防首报 | price_low 主口径；阈值 ±5% 可配置；静默学习期 <3 条快照不报 |
| 3 | 防重复 | 冷却 3 天 + 幂等键；notified 标记 |
| 4 | ID 漂移兜底 | detect_duplicates title 归一化（小写/去空白/去全角/去首尾标点），**只报告不自动合并**（防误并串基线） |
| 5 | 提醒出口 | alerts 表 → OpenClaw 心跳例行读 → 播报；无常驻 |
| 6 | 架构 | 自动下游 · 静默 · 波动才提醒；纯离线 |

**升级方向（答辩亮点）**：截尾均值窗口区间（去最高去最低取平均 ±区间，trimmed mean）——抗噪优于固定阈值，后续可替换/叠加固定阈值方案。

## 3. 设计决策记录（S1 关键取舍）

- **为什么 fetcher 降级**：PH 产品线是离线解析，monitor 无爬虫；B1 协议知识（状态码/ETag/限速）属**在线采集域**，归 factory-monitor 待修项；fetcher.py 保留为可选适配器不删
- **为什么归位 src/monitor**：monitor 是 PH 一级功能（overview.md 架构图与 api/web 平级），不是 modules/ 外围子模块——modules/ 是独立外围（factory-monitor/price-compare）
- **为什么数据目录独立**：`~/.pageharvest-data/monitor/`（PAGEHARVEST_DATA_DIR 覆盖），不跟代码包走（src 是 pip 包，data 不进包）
- **为什么不进 PyInstaller exe**：monitor 是后台自动化形态（cron 触发），不是用户 GUI 功能
- **为什么 csv 先 xlsx 后**：PH 产物格式未定，CSV 零依赖先通，xlsx 留 TODO（依赖定了再加）

## 4. 误解纠正（S1 答辩暴露的 3 个机制盲区）

1. **"冷却幂等键含价格档位，价格每次变就没用了"** → 对，这就是"一周 5 次提醒"根因。修复：冷却键改**商品维度**（同商品窗口内只报一次）+ **拐点报告**（趋势开始报"开始跌"，反转报"到位"，中间静默）
2. **"价格没变就不会报黄"** → 错。黄色=距低点≤10% + 斜率<0；**趋势窗口混入历史下跌段**（[10,8,8,8] 窗口含 10→8）→ 斜率恒负 → 平稳期误报。修复：低点/斜率取**滑动窗口内**，与低点窗口对齐
3. **"ID 变了商品还在监控里"** → 错。product_id 是唯一键，ID 变 = **新商品**（新 products 行）→ 无历史基线 → 永远卡学习期 → 静默。修复：title 归一化 detect → 报告疑似同品 → 人工确认合并（多维度：platform+title+店铺名）
4. **"防首报靠冷却器"** → 错（3 天轮批次 18，机制混淆）。**冷却幂等**（3 天 + 商品维度键）防的是**重复报**（同一事件不反复提醒）；**防首报**靠的是**静默学习期**——快照 <3 条不报，基线建立后再对比，首报必须相对稳定基线（如首次低于历史低点）才发。两机制各管一道闸门。

## 5. 费曼

> 一句话讲给外行：你收藏了一批商品，我每天默默记下它们的价格，只有价格**明显变**（比如跌超 5% 或跌破历史最低）才喊你一声——平时绝不出声，同一个商品三天内不会重复喊，商品链接换了我也能认出来。数据全在你本地，我不联网。

- Q: 设计 500 个选品的价格监控系统：数据从哪来？怎么判断波动？怎么防重复提醒？商品 ID 变了怎么办？提醒怎么出去？整体架构定位？
  A: - 6 考察点：① 数据入口（增量扫描 .monitor_scan_state，只处理新增/变化）② 波动判定（price_low 主口径 + 阈值 ±5% 可配置 + 静默学习期 <3 条不报）③ 防重复（冷却 3 天 + 幂等键 + notified 标记）④ ID 漂移（title 归一化 detect **只报告不自动合并**）⑤ 出口（alerts 表 + 心跳播报 + cron 无常驻）⑥ 架构（自动下游·静默·波动才提醒）
  - 亮点（答辩自创）：截尾均值窗口区间（去最高去最低取平均 ±区间）——抗噪优于固定阈值

- Q: 监控跑一周后三现象：A 商品"价格既是最低又是最高"还持续报；B 降价后处理了还反复提醒；C 商品链接换了监控静默。诊断根因分别是什么？
  A: - A：距低点 0% + **窗口混入历史下跌段 → 斜率恒负 → 持续报黄**（黄色=距低点≤10% + 斜率<0）
  - B：**冷却幂等键含价格档位 → 价格每次变 → 键每次新 → 冷却失效** + yellow 无幅度门槛
  - C：**ID 变 = 新商品 → 无历史基线 → 永远卡学习期 → 静默**（不是还在监控里）

- Q: 冷却幂等键含价格档位，为什么会导致"一周 5 次提醒"？拐点报告是什么？
  A: - 价格每次变 → 幂等键每次新 → 冷却失效（这就是反复提醒根因）
  - 修复：冷却键改**商品维度**（同商品窗口内只报一次）+ **拐点报告**（趋势开始报"开始跌"、反转报"到位"，**中间静默**）

- Q: 价格明明没变，为什么可能持续报黄？窗口边界怎么改？
  A: - 黄色 = 距低点 ≤10% + 斜率 <0；根因 = **窗口起点仍卡在历史下跌段内**（如 [10,8,8,8] 含 10→8）→ 窗口内斜率恒负 → 平稳期误报
  - 修复：低点/斜率取**滑动窗口内**并截断，与低点窗口对齐

- Q: 商品链接（ID）变了，监控为什么静默？怎么安全合并新旧商品？
  A: - ID 变 = 新商品（新 products 行）→ 无历史基线 → **永远卡学习期** → 静默
  - 修复三步链：title 归一化 **detect**（小写/去空白/去全角/去首尾标点）→ **只报告不自动合并**（防误并串基线）→ 人工确认合并（多维度匹配：platform+title+店铺名，标注来历可追溯）

- Q: monitor 在 PH 里的定位？完整数据链路？
  A: - 定位三词诀：**自动下游 · 静默 · 波动才提醒**；消费离线解析产物，纯分析无爬虫；PH 一级功能（与 api/web/cli 平级）
  - 链路：PH 解析产物（CSV）→ 定时扫描导入（增量）→ 跨批次比价 → 波动检测 → 明显波动写 alerts → 心跳播报；**无常驻进程**（cron 触发）；数据本地不上传

- Q: 防首报假警的机制是什么？和冷却器是一回事吗？
  A: - **两机制各管一道闸门**：防首报 = 静默学习期（快照 <3 条不报，基线建立后对比，首报须相对稳定基线）；防重复报 = 冷却幂等（3 天 + 商品维度键，窗口内同商品只报一次）
